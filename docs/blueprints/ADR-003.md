# ADR-003 — Bounded Contexts

## Status

Aprovado.

## Objetivo

Definir a divisão oficial do domínio do Turistei em Bounded Contexts independentes, permitindo evolução incremental, baixo acoplamento e alta coesão.

## Decisão

O Turistei será organizado em Bounded Contexts.

Cada contexto possui:

- responsabilidade própria;
- modelo de domínio próprio;
- regras de negócio próprias;
- ciclo de evolução próprio.

Nenhum contexto poderá assumir responsabilidades pertencentes a outro.

## Contextos Oficiais

### Core Domain

Responsável pelas entidades centrais do ecossistema.

Ownership:

- Local
- Usuario
- Plano
- Contrato
- Ownership

Nenhum outro contexto altera essas entidades diretamente.

---

### Catálogo

Responsável pela exposição pública.

Ownership:

- páginas públicas
- SEO
- categorias
- busca
- mapa
- vitrine
- CTA

Consome informações do Core Domain.

---

### Empresas

Responsável pela operação do estabelecimento.

Ownership:

- painel administrativo
- configuração do Local
- mídias
- conteúdo
- gestão operacional

---

### Marketplace

Responsável pela comercialização.

Ownership:

- produtos
- serviços
- experiências
- carrinho
- pedidos

Não altera o Core Domain.

---

### Reservas

Responsável por:

- agenda
- disponibilidade
- reservas

---

### Financeiro

Responsável por:

- assinaturas
- pagamentos
- comissões
- repasses
- auditoria financeira

Histórico financeiro é imutável.

---

### IA Elza

Responsável por:

- atendimento
- recomendação
- reservas assistidas
- vendas assistidas

A Elza nunca é proprietária dos dados.

Ela apenas consulta interfaces públicas dos demais contextos.

---

### Administração

Responsável por:

- usuários administrativos
- auditoria
- configurações globais
- monitoramento

---

### Notificações

Responsável por:

- e-mail
- push
- WhatsApp
- mensagens internas

## Dependências

Core Domain
← nenhum

Catálogo
← Core Domain

Empresas
← Core Domain

Marketplace
← Core Domain
← Empresas

Reservas
← Marketplace

Financeiro
← Marketplace
← Reservas

IA Elza
← Interfaces públicas

Notificações
← Eventos de domínio

## Regras

- Nenhum contexto acessa tabelas privadas de outro.
- Comunicação ocorre por interfaces bem definidas.
- Eventos de domínio poderão desacoplar integrações futuras.
- Cada contexto possui responsabilidade única.
- O Local permanece como Aggregate Root do ecossistema.

## Evolução

Novos contextos poderão ser adicionados futuramente sem alterar os existentes.

Exemplos:

- Fidelização
- CRM
- Marketing
- BI
- ERP
- API Pública

## Consequências

Toda modelagem física do banco deverá respeitar esta divisão de domínios.
